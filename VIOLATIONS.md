# AGENTS.md Compliance Audit — Findings

Generated by a 20-way parallel read-only audit against every rule in `.agents/AGENTS.md`
(rule 29's 22-item "Deep Audit" checklist split across 7 agents, the remaining ~20 rules
across 13 more). No files were changed to produce this report. Each finding lists **Priority**
(how much it matters) and **Complexity** (how much work to fix) separately — a few things here
are important but trivial to fix, others are low-stakes but would take real surgery.

Rules with zero findings across all 20 agents (not listed below): 2, 8, 9, 10 (shell
injection), 17, 18, 19 (sync I/O in body), 20 (both URL `==` and NSPredicate injection), 21
(observer token leak), 22, 23, 24, 25, 26, 28 (test isolation).

---

## High priority

### 1. `LocalHttpServerService.swift:111-124` — leaked `NWConnection` on malformed request
**Priority: High** — real, unbounded memory leak in a long-lived singleton (`static let shared`)
backing the HTTP-sharing feature. Every non-UTF8 chunk received while sharing is active leaks
one connection reference forever.
**Complexity: Simple** — the sibling failure branch two lines up already does the right thing
(`connections.removeAll(where: { $0 === connection })`); this branch is just missing the same
call before `connection.cancel()`.

### 2. `DiskSpaceVisualizerService.swift:47-61` — zombie `Task.detached` survives SwiftUI cancellation
**Priority: High** — rapid folder navigation can pile up multiple concurrent recursive disk
scans running in the background for folders the user already left, burning CPU/disk I/O.
**Complexity: Moderate** — `DuplicateDetectionService.swift` already solves the identical
problem correctly with `withTaskCancellationHandler` + per-iteration `Task.checkCancellation()`;
this is a "copy the existing pattern" fix, not new design.

### 3. `AutoOrganizationService.swift:119-127` (`processFolder`) — synchronous directory listing on `@MainActor` for a user-configured path
**Priority: High** — found independently by two separate audits. `rule.sourceURL` can point
anywhere the user configures, including `/Volumes/...`; a stalled network mount here blocks the
UI. This is exactly the "Anti-Beachball" scenario AGENTS.md rule 21 exists for, and the same
function already correctly detaches its *move* work — just not the initial scan.
**Complexity: Moderate** — wrap the `contentsOfDirectory` call in `Task.detached`, dispatch the
per-file rule matching back, same shape as the existing move logic just below it.

### 4. `DuplicateCleanerSheetView.swift` — header close (X) button
**Priority: High** — rule 30 explicitly and repeatedly bans this exact pattern ("every existing
sheet in this app closes exclusively through the footer, never through a header button"); this
is a visible, user-facing inconsistency against every other sheet in the app. Also missing the
mandated subtitle line and header background tint.
**Complexity: Simple** — remove the X button (Escape + footer Cancel/Done already close it),
add a one-line subtitle and `.background(Color(NSColor.controlBackgroundColor).opacity(0.5))`,
matching `AboutSheet`/`HelpSheet`/`SettingsView`.

## Medium priority

### 5. Missing `Task.checkCancellation()` in three async loops
**Files**: `DiskSpaceVisualizerService.swift` (recursive scan, see #2 — same fix covers both),
`PDFMergeService.swift:23,51` (page-by-page merge loop), `FileSystemService.swift:45,85`
(directory-listing loads).
**Priority: Medium** — `DuplicateDetectionService`, `FileShredderService`, `ThumbnailService`
already establish this as the expected pattern; these three are the outliers.
**Complexity: Simple–Moderate** — add `try Task.checkCancellation()` at the top of each loop
iteration.

### 6. `ArchiveInspectionService.swift:32` — silent `try? process.run()`
**Priority: Medium** — if `/usr/bin/unzip` fails to launch, the Archive Inspector sheet just
renders an empty list, indistinguishable from "this archive really has zero entries." No error
surfaces to the user (rule 29.12).
**Complexity: Simple** — the same file's `extractSingleEntry` already does this correctly
(`try process.run()`, propagates); mirror that.

### 7. 9 composite `Button` labels missing `.contentShape` (or using `Button` at all)
**Files**: `SidebarView.swift:170,335`, `DirectoryTreeNodeView.swift:50`, `PathBarView.swift:163`,
`ConnectToServerSheetView.swift:38`, `FolderPickerSheet.swift:64,161`, `AboutSheet.swift:37`,
`EmptyDirectoryView.swift:23` (lower confidence).
**Priority: Medium** — rule 33 flags this as a repeat offender because it reads to users as "the
button doesn't work" rather than a hit-testing subtlety; real UX bug, not cosmetic.
**Complexity: Moderate** — mechanical fix per rule 33's prescribed pattern (plain view +
`.contentShape(Rectangle())` + `.onTapGesture`), but 9 separate call sites to touch carefully
without regressing existing click behavior.

### 8. Window-scoped state living on shared `AppState` instead of `WindowUIState`
**Files**: `AppState.swift:70` (`quickLookURL`), `:77` (`selectedFavoriteURL`), `:48`
(`isEditingPath`).
**Priority: Medium** — rule 32 is a *previously shipped bug class* per its own text (opening
QuickLook/editing the path bar in one window would affect all open windows). Not yet confirmed
to have regressed, but matches the documented risk pattern exactly.
**Complexity: Moderate** — move each property to `WindowUIState`, update the (likely few) call
sites per property; same migration already done for other sheets/alerts per the file's own
history.

### 9. Hardcoded / non-localized strings
**Files**: `FooterBarView.swift:108` (**hardcoded in Portuguese**, not localized at all — the
most notable one), `SidebarView.swift:380`, `HeaderBarView.swift:178`, `MainContentView.swift:145`,
`AutoOrganizationSheet.swift:113`, `FilePropertiesSheet.swift:84` (borderline — proper noun).
**Priority: Medium** — rule 5 is "zero hardcoded text," and one of these ships non-English text
unconditionally regardless of the user's language setting.
**Complexity: Simple–Moderate** — add ~5 new `L10n` keys and route through `appState.tr(...)`.

### 10. `SidebarView.swift:366-380` — eject-volume button missing accessibility modifiers
**Priority: Medium** — icon-only button with `.help()` but no `.accessibilityLabel`/`.accessibilityHint`;
VoiceOver has zero fallback for it. Pattern is already correctly established elsewhere in the
same file (`DirectoryTreeNodeView.swift:191-192`).
**Complexity: Simple** — add the two missing modifiers, copy the pattern from the working example.

### 11. `Sources/Wiles/Views/Content/FileListView.swift:234-260` — `FileRowInteractionsModifier` duplicates `FileItemInteractionsModifier`
**Priority: Medium** — rule 1 explicitly names drag/context-menu/hover handling as must-not-duplicate;
this reimplements `onDrag`/`RightClickDetector`/context-menu plumbing that `FileGridView`/`FileColumnView`
already share via one modifier.
**Complexity: Complex** — consolidating requires extending the shared modifier with the row-specific
extra params (`springLoadedFolder`/`onTargetedChanged`) without regressing grid/column behavior;
real risk of subtle behavioral drift if rushed.

## Low priority

### 12. `AutoOrganizationService.swift:5` — class not marked `final`
**Priority: Low. Complexity: Trivial** (one keyword) — rule 3 says non-`@Observable`,
non-AppKit-wrapper classes should be `final`.

### 13. A few silent `try?` on encode/decode paths
**Files**: `AppState+ColumnsAndActions.swift:5`, `AutoOrganizationService.swift:39-40,46`.
**Priority: Low** — corrupted `UserDefaults` data silently resets rules/column state with no log;
annoying to debug but not user-data-destructive.
**Complexity: Simple** — add a log line; full user-facing error UI is probably overkill for a
background persistence path.

### 14. `ArchiveInspectionService.swift:35` — `readDataToEndOfFile()` buffers subprocess stdout in one shot
**Priority: Low** — archive *listings* are small text output even for large archives; the risk
is theoretical unless someone opens an archive with an enormous entry count.
**Complexity: Moderate** — would need a streaming reader instead of a one-shot read; not worth
it unless it's an actual reported problem.

### 15. `SmartFolderService.swift:60-78` — per-result icon fetch (`NSWorkspace.shared.icon(forFile:)`) inside the main-thread `NSMetadataQueryDidFinishGathering` callback
**Priority: Low** — bounded by Spotlight result-set size, not a large fixed collection; mild UI
hitch on searches with many matches, not a freeze.
**Complexity: Moderate** — would need batching the icon lookups off-main and dispatching back,
some restructuring of the completion closure.

### 16. Function-length violations (>25 lines, spot-checked, not exhaustive)
**Files**: `MainContentView.swift:387` (`handleArrowKeyDown`, ~36), `SidebarView.swift:234,271`
(~35, ~29), `AppState.swift:227,261` (`updateTrashSize`/`performEmptyTrash`, ~32/~31).
**Priority: Low** — maintainability, not correctness.
**Complexity: Simple–Moderate** — straightforward extraction into helper functions, same pattern
already used repeatedly this session (`AppStateOperationsFailureTests`, `ImageConverterCoverageExtraTests`
splits).

### 17. Untokenized magic numbers
**Examples**: `MainContentView.swift:319` (`stepMagnitude = 4.0`), `IntegratedTerminalView.swift:41`
(`+ 0.5`), `HeaderBarView.swift:86` (`+ 0.05`), plus widespread raw `.frame`/`.padding` literals
across most sheet views not routed through `LayoutTokens`.
**Priority: Low** — the sheet-sizing literals are pervasive enough across the codebase that the
auditing agent flagged them as possibly *accepted local practice* rather than an oversight —
needs a product decision, not just a mechanical fix.
**Complexity: Complex** if enforced everywhere (dozens of call sites); **Simple** for just the
2-3 named timing/step constants.

## Suggested order of attack

If picking off a handful: **#1 (leak) → #3 (beachball risk) → #4 (X button) → #2 (zombie task) →
#5 (cancellation checks) → #10 (accessibility)** covers every High item plus the cheapest Medium
wins in well under an hour of total work, none of it architecturally risky. #11 (DRY
consolidation) and #7 (contentShape sweep) are the two Medium items worth scheduling separately
since they touch the most call sites.
